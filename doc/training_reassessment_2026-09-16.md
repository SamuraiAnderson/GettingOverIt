# 任务复杂度与训练开销重评（2026-09-16）

结论：项目应按“高难度强化学习研究 + 尚待校验的训练系统”安排，不能按“现成 PPO 多跑几天就能通关”排期。现有单卡已经能支持局部验证。优先级应从继续堆探索模块，调整为：修复概率一致性 → 建立可重复的局部成功指标 → 对照实验 → 再考虑长程课程与规划。

本次只读取仓库、归档和硬件信息，运行无游戏的离线诊断；没有启动训练、修改训练实现或更换模型权重。最新训练证据来自 2026-07-26，并非本次实时吞吐测试。

## 1. 证据比原有结论更有限

- 15 个实验目录保存了 1,075 轮指标，buffer_size 合计 **5,961,500 个 agent-transition**。这是跨配置的已保存样本量，不是一个正确配置连续训练了近 600 万步；丢失、重复尝试及评估的开销也不在其中。
- `ou_me`：250 轮、160 万样本，精英池最佳 secured_dy 为 4.28 m；**234/250 轮（93.6%）只做 1 次 PPO minibatch 更新**。
- `p2_contact`：45 轮、18 万样本，精英池最佳 secured_dy 为 3.844 m；**44/45 轮（97.8%）只做 1 次 PPO minibatch 更新**。最后运行因 TCP `WinError 10053` 失败，不能当成完整完成的接触特征消融实验。
- `treefix2cont` 的精英池最佳值为 4.94 m。以上是“历史探索中最好的一条轨迹”的相对爬升，不是绝对海拔、平均表现或过障成功率。不同起点、时长和配方不能直接排名。
- 现有独立评估大多只有 1–8 个 episode，且没有最新两组的充分成功率评估。不能从精英池高度推断策略已稳定掌握某段技能。

因此，旧文档的“排除训练时长不足”“排除连贯探索不足”措辞过强。合理表述是：这些具体运行出现平台期，尚未完成足以排除实现问题和混杂因素的对照验证。OU、接触特征是否有效仍然开放。

## 2. 本次确认的训练实现缺陷

`actor_critic.py:get_action_and_value` 用原始 raw_action 计算 log_prob，再输出 `tanh(raw_action) * 100`；`evaluate_actions` 重算时却先将动作裁到 **±99.9**。当 `|raw_action| > atanh(0.999) ≈ 3.8002` 时，两端对应的动作不再相同。

调用现有采样/重算方法，只替换 forward 为固定高斯分布（OU φ=0.85，std=1，32,768 个二维样本），不做任何参数更新：

- raw 均值为 0：approx_kl ≈ 0.000019。
- raw 均值为 3：approx_kl ≈ **0.3403**，约 28.4% 样本的 ratio 超出 PPO clip 范围。
- raw 均值为 4：approx_kl ≈ **2.7269**。

这确认了动作边界上的概率往返不一致。最新精英池 4,000 个动作中，**21.85% 至少一轴超过 ±99.9**；精英池有选择偏差，不能把这个比例直接当作全部 on-policy 样本的比例。

另外，`ppo_trainer.py` 在 optimizer.step 前产生 ratio，之后用同一个 ratio 报告 KL。因而首个 minibatch 的巨大 KL 不是那一次参数更新造成的。历史日志与这个缺陷吻合，但尚未用真实 rollout buffer 对每条 old/new log_prob 逐项归因，不能声称它解释了全部平台期。

PPO 的概率比在同一策略、相同条件下应为 1；这个基本前提比继续调整 KL 阈值更优先。[PPO 原论文](https://arxiv.org/abs/1707.06347)。tanh 的逆变换本身也需处理数值问题，官方实现专门提示缓存与数值稳定性；本项目跨采样/更新阶段更适合保存 raw_action 并用稳定的 Jacobian 公式重算，不能仅靠放宽早停掩盖问题。[PyTorch TanhTransform 源码](https://github.com/pytorch/pytorch/blob/main/torch/distributions/transforms.py)。

## 3. 难度应按三个层次判断

**训练系统可信度：中等工程难度，当前有阻塞性缺陷。** TCP 同步、并行复制体、观测原语、归档大体已建立，但概率一致性、连接失败恢复、恢复训练后的随机状态与评估口径仍需验证。建议先给 1–3 个工程日的排障预算；这是工作量预留，不是修复完所有问题的承诺。

**固定起点、稳定翻越第一障碍：高难度连续控制，但可以明确验收。** 二维动作不代表问题简单：鼠标经平滑、增益和限力关节间接控制锤子，接触与离地会切换动力学。必须形成连贯动作，并把偶然的好轨迹变成可重复策略。目前没有足够证据给出达到成功率目标所需的样本数。

**从起点稳定完成整图：研究级、不确定性很高。** 当前固定起点的 400 步 rollout 在 50 Hz、stepFrames=1 下只覆盖约 8 秒；32 帧上下文约 0.64 秒。gamma=0.99 的折扣尺度约 100 步/2 秒，GAE 的权重衰减尺度约 16.8 步/0.34 秒。这些不是价值传播的硬上限（critic 可 bootstrap），但当前局部实验尚未验证长程路线、跌落恢复和多段技能衔接。

保留“不依赖人类示范”的项目约束。先修复后验证自主探索，再考虑发现轨迹驱动的课程、动作时间抽象或短时域搜索。不能仅凭 4–5 m 平台期判定全图不可行，也不能承诺追加若干 GPU 天一定通关。

## 4. 机器时间：采样成本可量化，成功成本未知

当前可见 GPU 为 **RTX 4070 / 12 GB**。默认 ActorCritic 共有 **1,123,013 个参数**，FP32 权重约 **4.28 MiB**。没有模型容量或显存不足的直接证据。

最近 `p2_contact` 的完整连续区间 iter297–335，共 39 轮，10 agents × 400 步：

- 平均一轮 **87.44 秒**，中位数 89 秒，P10–P90 为 80–93.4 秒。
- 采集 **61.67 秒（70.5%）**；PPO 阶段 **0.79 秒（0.9%）**；SIL **24.69 秒（28.2%）**；其余约 0.28 秒。
- 采集阶段约 **64.9 个 agent-transition/秒**；全流程约 **45.7 个/秒**。10 个 agent 合起来每轮 4,000 个样本；不应把 400 个同步环境步与 4,000 个样本混用。
- 更早同一目录 5 轮平均 173.8 秒；`ou_me` 的 16 × 400 配置平均 126.74 秒。主机负载和代码状态未受控，不能据此断言接触特征或 agent 数带来某个加速比。

用每轮 4,000 样本、约 87–174 秒作**当前异常早停流水线的场景换算**：

- 100 万样本：约 **6–12 小时**。
- 1,000 万样本：约 **60–120 小时（2.5–5 天）**。
- 1 亿样本：约 **600–1,200 小时（25–50 天）**。

这些是机器占用时间，不是达到目标的预测。没有把多次搜索失败、独立评估、停机或人工开发计入；正常计划可另留至少 25% 运维/评估余量。修复 KL 后 PPO 可能执行更多 minibatch，单位轮次会变慢，应重测：`每百万样本小时 = 每轮秒数 / 4000 × 1000000 / 3600`。例如每轮变成 180/300 秒时，每百万样本分别为 12.5/20.8 小时。

现在“更新很快”部分源自异常早停：1 次 batch64 / 4,000 样本只让约 **1.6%** 样本直接进入当轮 PPO minibatch；其余仍可能用于 GAE、效率图或精英筛选，所以不能说 98.4% 完全被丢弃。4 epochs 完整遍历原应有 252 个 minibatch，但有效 PPO 也可能合理提前停止，不以跑满 252 次为验收目标。

金钱开销需按实测整机功率与自己的电价换算：`电费 = 小时 × 整机平均 kW × 元/kWh`。当前未测训练负载下的整机功耗，也未查询云主机报价，不给虚假的确定金额；GPU 空闲读数和 200 W 功率上限都不等于训练整机功耗。

## 5. 性能优化的优先方向

- **先保证更新有效。** 保存 raw_action、稳定计算 squash Jacobian，并验证冻结策略时新旧 log_prob 一致；真实 buffer 的首个 minibatch KL 应接近数值误差，动作边界也应覆盖。
- **再测采集内部耗时。** 当前 `rollout.py` 对 agent 逐个做网络推理，同步复制体不等于 GPU 批量推理。可以评估批推理、减少 CPU/GPU 往返，以及 patch/接触几何构建耗时；目前 62 秒只有整体计时，不能全部归为 Unity 或 TCP。
- **避免按完整历史窗口重复存图像。** 4,000 个窗口 × 32 帧 × 4 × 32 × 32 × float32，仅 patch 就约 **1.95 GiB 主机内存**；6,400 窗口为 **3.125 GiB**。get_batches 的 np.array 又复制整个集合，单看这两份约 3.91/6.25 GiB，尚不含 minibatch、模型激活及其他对象。按帧存储、按索引组窗口更值得先测。
- **重测 SIL 的收益/成本。** 它占约 28% 时间，PPO 只有约 1%，当前总体近似“昂贵采样 + 精英自模仿 + 极少 PPO 更新”。修复后应做有/无 SIL 对照，而不是直接删除或加大它。

现阶段不建议仅为本项目购买更大 GPU 或租长周期算力；先 profile 并验证成功率曲线，再判断瓶颈是否转移到 GPU。

## 6. 下一批实验采用有上限的预算

1. **正确性门槛。** 离线概率往返验证 + 一次真实 rollout 的更新前一致性检查 + 正常范围的短跑。观察饱和比例、首批 KL、minibatch 数、分阶段耗时；不把修复完成等同于已解决探索。
2. **比较三种配方，每种三个独立训练 seed，每个 20 万样本。** 总计 180 万新样本。三个 seed 的训练重复与同一策略下十个 agent 采样不是一回事；独立 seed 是测鲁棒性，不是提高瞬时采样速度。按现流水线加 25% 余量约 **14–27 机器小时**；修复后重新换算。首轮筛选预算可设 **24–48 机器小时上限**，这是试验预算而非通关承诺。
3. **固定评估集。** 明确真正过障的位置/状态条件，分别报告无探索噪声和指定随机策略的成功率、守住高度、跌落率、到达用时；有希望的候选至少做 100 次带轻微初态扰动的独立 episode，并保留不确定区间。不要再用历史精英最大高度作为唯一验收指标。
4. **没有可重复进步就停止扩大样本。** 达到预算上限仍未优于修复后的基线，应改变动作时间表示或探索机制；先证明第一段能稳定完成，再为整图另立预算。
