# 已知结论

这里汇总项目跑出来的、可复现的核心结论，方便协作者一眼看清"目前已经知道了什么"，不必在多个专题文档间翻找。其中相当一部分是负面结果——多数实验的价值在于**排除一个假设**，而不是证实一个假设。

每条只给通俗摘要 + 结论意味着什么，详细证据与数据留在各自的专题文档里（见每条末尾的链接），本文不重复。

> **写法准则**：每条结论都力求区分**观测事实**（在哪次实验、哪个配置下看到了什么）与**当前最佳解释**（据此推测的原因，可被后续证据推翻）——**"我们这么试失败了" ≠ "这个方案不可行"**。仍未尝试的路径会显式列在"仍开放"里，防止把"某次尝试的负面结果"读成"方案的判决"。

## 1. 环境的确定性有一个 ~1e-4 的地板

**观测**：同一个快照重置后重跑零动作序列——
- **静止姿态**：逐帧累计误差 ≈ 9e-5（≈1e-4），首帧最好可低至 2e-7；
- **摆动姿态**：同样的零动作被放大到 ~0.1–0.15（分歧集中在角速度 / 锤角，呈拍频形态而非指数爆炸）；
- **激烈动作**：由确定性混沌进一步放大到 O(数十)。

**当前最佳解释**：快照能保存每个刚体的位置、速度、角度；但物理引擎内部还缓存"上一帧接触/关节冲量"用来加速下一帧求解。这个量既没有公开接口读取、也不在刚体状态里，所以快照存不下：

```text
快照能存：  每个刚体的 位置 / 速度 / 角度        （有公开接口，能读能写）
快照存不了：物理引擎缓存的“上一帧接触/关节冲量”  （无接口、不在刚体状态里）

→ 每次重置，引擎都只能从“零冲量”重新算
   ↳ 这构成一个 ~1e-4 的种子，始终存在
      · 静止姿态下不被放大 → 累计误差就停在种子量级（~9e-5）
      · 摆动姿态被拍频放大 → ~0.1
      · 激烈动作被混沌放大 → 更大
```

**意味着什么**：把游戏当作"**逐位精确**的世界模型"做不到；但当作**近似的、短时域滚动重规划**用是可以的——1e-4 种子对候选排序基本鲁棒（所有候选从同一快照出发，同放大同缩小）。

**仍开放**：让启动姿态可靠收敛到静止（消除摆动抽签）能让零动作诊断稳定全绿；对激烈动作下的混沌放大无能为力——这是引擎级下限，不是配置问题。

> 详细验证（P0–P4 各断言、静止 vs 摆动姿态、修复清单）见 [planb_premise_verification.md](planb_premise_verification.md)。

## 2. 我们目前的尝试都卡在硬探索这一关

**观测**（截至 `ou_me` 实验）：

| 实验 | 配置 | 结果 |
|---|---|---|
| `treefix2`（190 轮） | 50Hz + iid 高斯采样 | 精英轨迹 top-10 全在起点附近横向游走，峰值高度 y ≈ 0~1 米，无一翻越第一个障碍（Deadtree, x ≈ -30） |
| `treefix2cont`（+70 轮） | 同上续训到 260 轮 | 仍无纵向价值传播——排除"训练时长不足" |
| `ou_me`（250 轮） | + OU 时序相关噪声 + MAP-Elites 精英池 | 守住高度推到 4.28 m 后停住，占据 cell 数停在 11 |

**当前最佳解释**：
- **直接原因**：控制频率 50Hz、每帧独立采样。翻过第一个台阶需要一段跨约 25 帧、前后连贯的"勾—拉"动作——25 次互相独立的随机采样凑出这样一段连贯动作的概率几乎为零。
- **系统性原因**：奖励塑形、模仿学习、轨迹评分这些机制**全都在探索的下游**。上游没撞对第一段真攀爬 → 没有正样本 → 下游机制退化成"把起点乱晃强化得更熟练"。稀疏奖励 + 硬探索的经典死锁。

**仍开放**（重要——**这是对上表这些具体尝试为什么失败的诊断，不是对 PPO/RL 方案本身可行性的否定**）：
- roadmap 里 **P2.2**（接触条件双 actor 头）、**P3.1/P3.2**（相位加权信号）、**P4.1**（把动作重参数化成笔画基元）、**P4.2**（游戏当近似世界模型做 MPC 搜索作为探索引擎）都**还没试**。
- 从 ou_me 把守住高度从 ~1 m 推到 4.28 m 看，方向对了、还在动，只是每一小步都很难。
- 结论 4 的"动作低频"分析给出了明确的下一步方向：把探索先验放到低频薄流形上。

> 各优化项的动机、依赖与验收信号见 [optimization_roadmap.md](optimization_roadmap.md)；实验的原始指标与结论见 [runs/README.md](../runs/README.md) 及各 `runs/<tag>/RESULT.md`。

## 3. 只靠平台跳跃走不通这张地图（分析下界，不是地图判决）

**观测**（用了什么方法得到什么数）：
- 离线可达性分析（`effectiveness_report.md` A–E 五项）把地图抽象成"可着陆平台之间的跳跃图"，用作弊级理想势场（直接给出到山顶的测地距离）做贪心攀爬。
- 结果：跳跃距离 reach=16 m 时爬升高度占比中位数只有 **6.0%**、到顶率 **0%**；放大到 reach=32 m 仍无法稳定到顶。

**这个分析不能推出什么**（关键，勿越界解读）：
- 分析**没建模**游戏里靠锤子摩擦攀爬垂直墙面的能力。
- 所以结论只是"**靠平台跳跃这一类策略**"的下界——**不能**当作"地图有几何断裂"或"地图不可通过"的证明。
- 真实策略必然要用爬墙能力，纯几何可达性分析会**低估**真实可达性。

**意味着什么**：
- 读这份可达性数字时，记住这是保守下界；别据此判决地图或策略的物理上限。
- 依赖平台跳跃的探索/规划策略要慎用；爬墙能力必须进入策略空间才能真正解决问题。

> 完整分析（A–E 五项及方法学局限）见 [`src/Data/analysis/effectiveness_report.md`](../src/Data/analysis/effectiveness_report.md)。

## 4. 能完成攀爬的动作是"低频"的

**结论**：对能完成攀爬的目标动作做频谱分析，能量几乎全部（约 100%）集中在 4Hz 以下，是一条又慢又平滑的曲线。而 PPO 默认用的独立高斯噪声正好相反——相邻两帧几乎不相关，能量均匀散布在所有频率上。两者的频率结构几乎不重叠。

**通俗理解**：目标动作像一笔"慢慢画出来的连贯笔画"，而独立高斯噪声像"每帧乱抖"。用乱抖的噪声去碰巧凑出一笔连贯笔画，概率极低：

```text
目标攀爬动作：能量集中在 4Hz 以下       （慢、连贯、像一笔画）
iid 高斯噪声：相邻帧几乎不相关，能量摊平到全频段（快、乱、每帧独立抖）
     → 两者频率几乎不重叠 → 噪声很难凑出攀爬动作
时序相关噪声（OU / 粉红噪声）：相邻帧强相关、能量偏低频 → 和目标基本重叠
```

**意味着什么**：这是把探索噪声从"独立高斯"改成"时序相关（OU / 粉红噪声）"的直接依据；也说明 50Hz 逐帧决策极大浪费了搜索预算（后续可考虑把动作重参数化成"笔画基元"）。

> 依据与落地（OU 噪声如何保证 PPO 数学正确、笔画重参数化设想）见 [optimization_roadmap.md](optimization_roadmap.md) 的 P1.1 与 P4.1。
>
> 注：目标动作侧频谱分析的原始脚本（`ideal_action.py`）当前不在仓库内；`src/tests/analysis/viz_exploration_noise.py` 只覆盖噪声侧的时序结构可视化。若要让这条结论可从仓库完整复现，需把目标动作侧的频谱分析补进 `src/tests/analysis/`。
