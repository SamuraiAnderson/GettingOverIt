# 验证体系

环境的价值取决于它是否可信。项目的验证分四类，**最大的区别是要不要真的把游戏拉起来**——这决定了它能不能塞进批量运行、也决定了你改完某处代码后该重跑哪些。

本文讲清四类验证各自管什么、以及"改了哪层要重跑哪层"。具体到每个脚本覆盖什么内容，见 [`src/tests/README.md`](../src/tests/README.md)（脚本级清单的唯一权威，本文不重复罗列）。

---

## 一、四类验证

| 类别 | 位置 | 要不要游戏 | 快不快 | 怎么跑 |
|---|---|---|---|---|
| 离线单元测试 | `src/tests/training/test_*.py` | 否 | 秒级 | `python -m src.tests.run_unit_tests` |
| 离线分析 / 基准 | `src/tests/analysis/` | 多数不需要 | 秒到分钟 | `python -m src.tests.analysis.<name>` |
| 在环集成测试（L1–L9） | `src/tests/control_interaction/` 等 | **是** | 慢（要启动游戏） | 单独运行 |
| 历史标定 | `src/tests/input_characteristics/` | 是（已完成） | 归档 | 一般不再跑 |

### 1. 离线单元测试

纯计算，不碰游戏进程，秒级完成。覆盖接触信号几何、维度算术、探索噪声与精英池、光栅化正确性等。

环境里没装 pytest，每个测试脚本都自带 `main()` 能独立自跑；运行器只是把它们逐个以子进程拉起再汇总：

```bash
python -m src.tests.run_unit_tests            # 全部
python -m src.tests.run_unit_tests -k patch   # 只跑名字含 patch 的
```

### 2. 离线分析与基准

产出图表和量化结论，多数写到 `src/Data/analysis/`。用来校验几何/栅格化的正确性、量化探索噪声的时序结构、标定奖励权重等。多数不需要游戏（个别如精英轨迹可视化需要）。

### 3. 在环集成测试：L1–L9 能力阶梯

按能力分层递进，全部需要游戏进程。设计上每一层验证的都是**上一层成立之后才有意义的性质**——底层不通，上层测了也没用。

| 层 | 验证目标 |
|---|---|
| L1–L2 | TCP 能连通、输入和状态之间有因果关系 |
| L3 | 同一串输入重跑结果可复现 |
| L4 | 输入幅度越大、响应越强（剂量关系） |
| L5 | 多 agent 之间互相隔离、并行输入不串扰 |
| L6 | 收集到的碰撞体和游戏里实际几何对齐 |
| L7 | 能提取可着陆表面、生成空投候选点 |
| L8 | 批量投放后落差统计合理 |
| L9 | 无噪声推理评估；落水复位行为正确 |

### 4. 历史标定

游戏输入精度与有效范围的标定，已经跑完并固化成常量（精度 1.0、有效范围 [10, 100]、饱和点 100）。归档性质，一般不用再跑。

## 二、改了哪层，重跑哪层

这张表帮你在改动后快速定位最小验证范围，避免"改一行跑全套"或"该跑的没跑"。

| 你改动了… | 最小验证 | 说明 |
|---|---|---|
| 训练侧纯 Python 逻辑（观测构建、奖励、模型、数据集、噪声、精英池） | 离线单元测试 `run_unit_tests` | 秒级，不需要游戏，改完就应该跑一遍 |
| 接触信号 / 几何 / 光栅化 | 离线单测 + 对应离线分析（`check_tip_patch_coverage`、`diagnose_tip_rasterization`、`verify_mask_aliasing`） | 几何正确性除单测外还有专门的分析脚本 |
| C# 插件（`src/GameRuntime_v2/`）| 先编译（见 [toolchain.md](toolchain.md)），再跑相关在环测试 | 改协议/状态维度 → L1–L3；改输入注入 → L4；改复制体 → L5；改碰撞收集 → L6 |
| TCP 协议 / 状态维度 | L1–L3（连通、因果、可复现） | 协议是所有交互的契约，动它必须重跑底层 L 系列 |
| 空投 / 落点筛选 | L7 → L8 | L7 出候选点，L8 验证批量投放 |
| 模型推理 / checkpoint 格式 | L9 模型评估 | 无噪声推理，结果落到 `runs/_eval/` |
| 快照 / 重置 / 确定性相关 | `test_planb_premise.py`（在环） | 验证跨 reset 可复现性，见 [findings.md](findings.md) 与 [planb_premise_verification.md](planb_premise_verification.md) |

> 经验法则：**只动 Python 训练侧就跑离线单测；动了 C# 或协议就要重编译 + 重跑在环 L 系列。** 在环测试慢且要占用游戏，按上表挑对应层跑，不必每次全套。
