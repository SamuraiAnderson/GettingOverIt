# 控制交互测试结论

## 测试层次总览

| 层次 | 名称 | 脚本 | 结果 |
|------|------|------|------|
| L1+L2 | 协议 + 因果 | `test_l1_l2_protocol_causality.py` | PASS |
| L3 | 可重复性 | `test_l3_repeatability.py` | PASS（短序列） |
| L4 | 序列稳定性 + 区分性 | `test_l4_dose_response.py` | 稳定性 FAIL / 区分性 PASS |
| L5 | 多 Agent 独立性 | `test_l5_agent_isolation.py` | 同动作一致性 FAIL |

---

## L4 — 单 Agent 确定性（关键发现）

### 测试条件

- `num_agents=2`（C# 侧 `numDuplicates=2`，观察 agent 0）
- `amplitude=300`，`n_steps=500`，`n_trials=5`，`action_mode=random`（固定种子 42）
- 每次 trial 从同一快照 reset，执行完全相同的动作序列

### 结果

**稳定性（Scenario A）：FAIL**

两次独立运行均出现严重偏离：

| 运行 | 最大偏差维度 | max_diff |
|------|------------|----------|
| Run 1 | angular_velocity | 51.7 |
| Run 2 | hammer_angle | 332.0 |

同一动作序列、同一快照出发，5 次 trial 的终态轨迹大幅发散。

**区分性（Scenario B）：PASS**

不同动作序列（零 / 右 / 左 / 上 / 下）的终态在状态空间中清晰可分。

**跨 session 一致性：FAIL**

两次运行的 warmup 基线（player 位置）不一致，说明即使 warmup 阶段也存在不确定性。

### 结论

> Unity Physics2D 即使在 Script 模式下（`Physics2D.simulationMode = Script`，手动调用 `Physics2D.Simulate(dt)`），对于复杂关节系统（Getting Over It 的铁锤 + 人体多关节链），**物理求解器本身不是确定性的**。

可能原因：浮点累积、约束求解器迭代顺序、Rigidbody2D 内部缓存状态在 Reset 时未完全清零。

## L5 — 多 Agent 独立性

### 测试条件

- `numDuplicates=2`，两个 agent 共享物理世界
- `n_steps=50`

### HEAD 原始代码结果

| 情形 | 含义 | 结果 | 备注 |
|------|------|------|------|
| X（同动作一致性） | agent 0 与 agent 1 执行相同动作 | max_diff=0.495 | 预期 < 1e-3 |
| Y（不同动作区分性） | agent 0 向右，agent 1 向左 | FAIL | 终态无法区分 |
| Z（物理干扰） | agent 0 施力，agent 1 静止 | FAIL | agent 1 速度受影响 |

### PlayerDuplicateManager 三分支重构后

- Scenario X max_diff 恶化到 13.4（初始角度偏移约 1°）
- 原因：`SyncRigidbodiesFromOriginal` 将速度清零（而非拷贝），`FixJointConnections` 禁用外部关节导致初始平衡被破坏

### 结论

> 克隆体与原始 Player 之间存在初始状态偏差（HEAD 已有 0.495），三分支重构进一步恶化。在 L4 已证明的物理非确定性背景下，多 Agent 的轨迹一致性目标不可达。

## 已修复的问题

### agent 0 在 num_agents=1 时输入无效

**根因**：`PlayerInputService.InitializePlayerControl()` 获取了 `input_enabled` 字段但从未设置为 `true`。而 `PlayerDuplicateManager` 对复制体显式设置了 `input_enabled = true`。当 `numDuplicates=1`（无复制体）时，原始 Player 的 `input_enabled` 保持游戏默认值（可能为 `false`），导致 `FixedUpdate()` 跳过输入处理。

**修复**：在 `PlayerInputService.InitializePlayerControl()` 中添加 `inputEnabledField.SetValue(playerControlComponent, true)`。

**提交**：`22780dc fix: set input_enabled=true for original Player, fixing input not working with num_agents=1`

## 对 AI 训练的影响

1. **不能假设确定性映射**：`f(s0, actions) = s_n` 不是确定性函数，world model 的训练目标应该是分布（distribution）而非点估计（point estimate）。

2. **多 Agent 并行采集仍可行**：虽然轨迹不完全一致，但每个 agent 独立产生的轨迹仍然是有效的训练样本。关键是放弃"轨迹一致性"假设，将每个 agent 视为独立的数据源。

3. **PlayerStateService / PlayerDuplicateManager 修改暂缓**：三分支重构严重影响初始状态，在物理非确定性前提下，精细的初始状态对齐收益有限。两文件保持 HEAD 原始状态。
